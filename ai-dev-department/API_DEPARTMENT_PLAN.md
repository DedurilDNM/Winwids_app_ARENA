# План: API-отдел агентов (общий котёл ключей, роли, скиллы, инструменты)

## Цель

Второй «движок» рядом с браузерными аккаунтами: агенты работают через API-ключи.

- **Общий котёл ключей.** Вы добавляете ключи (OpenRouter, Anthropic, Groq, DeepSeek,
  любой OpenAI-совместимый агрегатор). Каждый запрос агента берёт самый свободный ключ
  нужного агрегатора. Ключ получил лимит → запрос сразу уходит на другой ключ, а
  лимитный ключ проверяется в фоне раз в 5 минут и сам возвращается в «доступен».
- **Роли.** Для каждой роли (Оркестратор, Архитектор, Кодер, Ревьюер, Тестер, …) вы
  выбираете агрегатор, модель, скиллы и инструменты.
- **Отдел из субагентов.** Ведущий агент (оркестратор) раздаёт задачи субагентам по
  ролям, в том числе параллельно, и собирает результат.
- **Скиллы как в Claude Code.** Папка со `SKILL.md` (имя и описание в начале файла,
  инструкции ниже, рядом файлы). Агент видит список скиллов и загружает нужный сам.
- **Инструменты как в Claude Code.** Read, Write, Edit, Glob, Grep, Bash, WebFetch,
  TodoWrite, Skill, Task (вызов субагента). Работают только внутри рабочей папки запуска.

## Архитектура

```
UI (котёл ключей · роли · скиллы · запуски)
        │ REST + WebSocket
server/app/agents/
  providers.py   каталог агрегаторов: адрес, проверка ключа, список моделей
  keypool.py     выбор ключа, ротация, статусы, фоновая проверка раз в 5 мин
  llm.py         единый вызов модели с инструментами:
                   Anthropic — официальный SDK `anthropic`
                   остальные — OpenAI-совместимый протокол (httpx)
  tools.py       инструменты, ограниченные рабочей папкой
  skills.py      реестр скиллов (встроенные + ваши)
  runtime.py     цикл агента: модель → инструменты → модель …
  department.py  ведущий агент + субагенты, события, сохранение запуска
server/app/api/  keys.py · agent_roles.py · skills.py · runs.py
```

Почему цикл агента свой, а не готовый хостинг агентов: ключи разных агрегаторов и их
ротация есть только в своём цикле; управляемые агенты Anthropic работают только с
моделями Claude и своим хостингом.

### Ключ: состояния

| Статус | Когда | Что дальше |
|--------|-------|------------|
| `available` | проверка прошла | раздаётся агентам |
| `limited` | 429 (лимит запросов) или 402 (кончились кредиты) | не раздаётся; проверка раз в 5 мин (не раньше `Retry-After`) |
| `invalid` | 401/403 | не раздаётся; проверка раз в час и по кнопке |
| `disabled` | выключен вами | не трогается |

Выбор ключа: доступные ключи агрегатора → меньше всего запросов «в работе» → дольше
всех не использовался. Все ключи в лимите → агент ждёт ближайший освобождающийся ключ
(видно в интерфейсе), а не падает.

Проверка ключа: крошечный запрос (1–16 токенов) к той модели, на которой ключ упёрся в
лимит; для OpenRouter ещё `GET /api/v1/key` (остаток кредитов).

### Безопасность

- Ключи хранятся зашифрованными (Fernet, как токены GitHub), в интерфейсе видны только
  последние 4 символа, в логи не пишутся.
- Файловые инструменты не выходят за рабочую папку запуска (проверка путей, без
  символических ссылок наружу).
- Bash: рабочая папка, тайм-аут, ограничение вывода, окружение без ключей и секретов
  сервера; если на сервере есть `bwrap` — запуск в песочнице. Bash можно выключить
  для роли.

## Как пользоваться (этапы 2–5)

1. «Отдел» → «Котёл ключей» → «Ключ в котёл»: агрегатор, ключ, название. Ключ сразу проверяется.
2. «Роли»: для Оркестратора и нужных ролей — агрегатор и модель (список моделей приходит
   от агрегатора), инструменты, скиллы. Ненастроенная роль берёт агрегатор с ключами и его
   модель по умолчанию (у Anthropic — `claude-opus-5-5`).
3. «Скиллы»: встроенные (`code-review`, `write-tests`, `debugging`, `frontend-design`) и ваши —
   SKILL.md или .zip с папкой скилла.
4. «Запуски»: опишите задачу → «Запустить отдел». Видно дерево агентов, план ведущего,
   шаги вживую, итог, файлы рабочей папки (скачать .zip).

Для моделей Claude 5.5 и Fable 5.x включён серверный запасной вариант при отказе модели
(`fallbacks: "default"`): если классификатор безопасности отклонит запрос, его повторит
запасная модель. Bash агентов: поставьте `bubblewrap` (`sudo apt install bubblewrap`), тогда
команды идут в песочнице, где не видно `.env`, базы и домашней папки сервера.

## Референсы интерфейса

- Linear и Vercel (Geist): тёмная плотная панель, палитра команд ⌘K, статусы-«пилюли»,
  моноширинные цифры. → Вариант **A «Командный центр»**.
- [Agents Office](https://towardsdatascience.com/agents-office/): агенты как люди в
  офисе — сразу видно, кто работает, ждёт или застрял. → Вариант **B «Студия»**: светлый,
  тёплый, карточки-персонажи, котёл ключей как «бак» с уровнем.
- Многоагентное дерево с бейджами статуса и расходом токенов по веткам — для экрана запуска
  в обоих вариантах.
- Отладчик вместо ленты чата: шаги агента (инструмент, файл, итог) раскрываются по клику.
