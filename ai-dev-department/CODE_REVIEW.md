# Ревью кода: что можно оптимизировать (записано, не сделано)

Приоритет: **В** — высокий (скорость, надёжность), **С** — средний, **Н** — низкий (удобство).

## Адаптер браузера (`server/app/adapters/generic/adapter.py`, ~1400 строк)

1. **В. Много обращений к браузеру на каждый опрос.** `wait_response` каждые 2 с делает
   5–7 отдельных вызовов (`get_state`, капча, метка перезагрузки, число сообщений, текст).
   Резервное чтение ответа дважды за опрос сканирует весь DOM (`body *` +
   нормализация текста). Решение: один `evaluate` на опрос, который возвращает
   `{state, captcha, reloaded, count, text}`. Найденный «якорь» (наше сообщение)
   запоминать в странице, а не искать заново.
2. **В. `_first_visible` — по вызову `is_visible()` на каждый элемент.** Заменить на
   `locator(...).filter(visible=True).first` или один `evaluate`.
3. **С. JS выбора режима и модели сканирует все элементы с `getComputedStyle`.** На больших
   страницах это дорого. После первой находки ограничить поиск поддеревом панели
   инструментов.
4. **С. Пометка `data-aidd-seen` на все элементы перед каждой отправкой** — O(N) записей
   в DOM. Дешевле один `MutationObserver`, который помечает только новые узлы.
5. **С. Файл слишком большой.** Разбить: `js/*.js` (скрипты страницы отдельными файлами),
   `reader.py` (чтение ответа), `setup.py` (режим и модель), `login.py`, `blockers.py`
   (капча, окна). Проще тестировать и читать.
6. **Н. 26 вызовов `getattr(self.settings, "X", default)`.** Значения по умолчанию уже есть
   в `Settings`. Если в тестах использовать настоящий `Settings`, `getattr` не нужен.
7. **Н. Жёсткие `asyncio.sleep(0.5…2.0)` по коду.** Вынести в одну настройку «темп» —
   тесты станут быстрее.

## Оркестратор (`server/app/services/orchestrator.py`, ~1400 строк)

8. **В. Классификация ошибок по подстрокам** (`_PERMANENT`, `"login" in msg`,
   `"is not selected"`). Любая смена текста ошибки ломает логику повторов. Нужны типы
   исключений: `Transient`, `NeedsHuman`, `ConfigError`, `ReplyFormatError`.
9. **В. Таймаут плана или ревью сразу роняет проект** (`_Chat.ask` пробрасывает
   `TimeoutError`). Для оркестратора нужен 1–2 повтора в новом чате.
10. **С. Разбить файл**: `plan_parser.py` (`parse_task_plan`, `_repair_json`,
    `parse_review`), `chat.py` (`_Chat`), `runner.py` (`_Run`), `ci_step.py`.
11. **С. `data/replies/*.txt` копится без ограничений.** Хранить последние N на проект
    или чистить через 14 дней.

## Сервер и развёртывание

12. **В. `uvicorn.log` растёт бесконечно** (`StandardOutput=append:`). Перейти на journald
    или `RotatingFileHandler` (например 10 МБ × 5).
13. **В. Перезапуск `aidd` помечает идущие проекты как «ошибка»**
    (`fail_interrupted_projects`). Вместо этого продолжать их автоматически через resume.
14. **С. Память: на каждый аккаунт свой Camoufox и Xvfb, даже без работы.** Простаивающие
    браузеры можно закрывать через N минут и поднимать из `storage_state` по требованию.
15. **С. Три скрипта развёртывания повторяют одни куски** (Caddyfile, `set_env`, юнит
    systemd). Вынести в `deploy/lib.sh`. `setup-domain.sh` и `setup-tailscale.sh` пометить
    как альтернативы. Юнит `aidd` создаёт только `setup-domain.sh`, а
    `setup-cloudflare.sh` на него рассчитывает — юнит должен создаваться в одном месте.
16. **Н. Настройки адаптера правятся через `sed` по `.env`** — нужна страница настроек
    (см. план, F).

## Интерфейс (`web/`)

17. **С. «Нужна помощь» опрашивается каждые 8 с** (`attention.js`), хотя WebSocket уже есть.
    Перейти на push по WS: меньше запросов, мгновенные уведомления.
18. **Н. Пульс агента** («думает 2:31…») не показывается — данные есть на сервере.

## Тесты

19. **В. Тесты в браузере запускают Chromium на каждый тест** (≈10 тестов по 3–10 с).
    Один браузер на всю сессию (fixture `scope="session"`) сократит полный прогон
    примерно с 5 до 2 минут.
20. **С. e2e-скрипты живут в `/tmp`** (`e2e2.sh`), их нет в репозитории. Перенести в
    `web/tests/` и добавить `make test` / `make e2e`.
21. **С. Фейковый сервис не похож на текущий настоящий** (Text-режим, скрытые чаты,
    кнопка модели в виде `div`). Обновить по снимку структуры (план, C и E).
